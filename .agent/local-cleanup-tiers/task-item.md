# 实施计划：本机清理分层（轻量清理 / 彻底清理）

- [ ] 1. 建立清理档位模型与统一落点清单
   - 在 `internal/app/local_cleanup.go` 中新增档位枚举 `CleanupTier`（`light` / `full`）及解析函数，非法取值返回错误而不是回退
   - 定义档位解析规则：空值按 `full`，与引入档位前行为一致
   - 扩充清理结果结构，携带实际执行的档位标识，并保持旧字段不变
   - _需求：1.1、1.2、1.5、8.1_

- [ ] 2. 为每个候选落点补齐档位归属判定
   - 在现有落点枚举上为每一项标注 `light` 下属于清理还是保留，判定与枚举共用同一来源，不新增第二套扫描逻辑
   - 保留面：`~/.dec/config.yaml`、SSH 密钥与 `config.d/dec*`、`~/.ssh/config` 的 Dec Include 行、项目 `.secrets` 凭据落地、项目 Git fragment、`~/.gitconfig` 的 Dec 条目、项目 `.dec/config.yaml` 的 requires、`~/.dec/secrets` 与 `~/.dec/pruned`
   - 清理面：各 plane 的 `dec-*` skills / commands / rules 与内置 skill、各 IDE MCP 配置中的 Dec 条目、`~/.dec/cache` 与项目 `.dec/cache`、`~/.dec/repo.git`
   - 无法证明归属 Dec 的候选在两个档位下都保留，并附带保留理由
   - _需求：1.3、1.4、2.1、2.2、2.4、2.5、2.6、2.7、2.8、2.9、2.10_

- [ ] 3. 让执行路径按档位跳过凭据撤销与配置删除
   - 在清理循环中依据档位归属过滤动作，`light` 下跳过 GCM 凭据撤销、密钥与配置片段删除、全局与项目配置删除
   - 保持 `repo.git` 与各级 cache 在两个档位下都清理，并确认下次拉取会触发自动 clone
   - 保持 Console、运行时套件、当前服务实例与集成测试落点的既有保护语义，两档一致
   - _需求：2.3、2.9、8.2、8.3、6.1_

- [ ] 4. 让预览按档位计算并列出保留项
   - 为预览增加档位参数，使用与执行阶段相同的归属判定逻辑，保持只读
   - `light` 下额外返回「本档位保留、彻底清理会删除」的条目清单
   - 无任何可清理项时返回明确结论
   - 执行阶段不复用预览结果，重新计算候选
   - _需求：3.1、3.2、3.3、3.4、3.5_

- [ ] 5. 实现两档确认门槛
   - `full` 保留确认词「清理本机」
   - `light` 使用与 `full` 区分的确认文案，明确说明配置与凭据不会被删除
   - 缺少确认或档位非法时拒绝执行，错误信息中带上档位
   - _需求：4.1、4.2、4.3、4.4_

- [ ] 6. 完善结果摘要与执行记录
   - 按「删除 / 修改 / 撤销凭据 / 保留」分类输出计数与明细，失败项逐条给出原因且不阻断其它条目
   - `light` 结果中列出本次保留的用户手工积累项，并提示执行一次拉取即可恢复
   - 在事件流与操作历史中记录本次执行的档位
   - _需求：5.1、5.2、5.3、5.4_

- [ ] 7. 打通请求层与 Console 的档位传递
   - 在 `internal/servicehost/dispatch.go` 中为本机清理的预览与执行接入档位参数，缺省仍为 `full`
   - 在 `client/src/pages/settings-page.tsx` 清理面板增加档位选择，默认轻量清理
   - 切换档位时清空上次预览与确认输入；`full` 保留红色不可撤销警示，`light` 使用描述两档差异的提示
   - 执行完成后按档位展示摘要与恢复提示
   - _需求：7.1、7.2、7.3、7.4、8.1_

- [ ] 8. 补充后端单元测试
   - 对同一组 fixture 落点分别断言 `light` 与 `full` 的删除 / 保留判定，覆盖配置、凭据、secret、隔离区四类保留面
   - 覆盖缺省档位解析为 `full`、非法档位拒绝、缺少确认拒绝三条路径
   - 覆盖预览在 `light` 下返回保留项清单且不产生文件副作用
   - _需求：9.1、9.2、9.4、1.2、3.3_

- [ ] 9. 补充轻量清理到恢复的闭环测试
   - 用 fake 资产面与本地 Git 仓库模拟轻量清理后执行一次拉取
   - 断言资产恢复可用，且不要求重新配置私仓地址、凭据、项目导入与资产勾选
   - 断言项目 requires 声明的资产集合与清理前一致
   - _需求：6.1、6.2、6.3、9.3_
