# 0060 Windows 管理面窗口不占任务栏位置

## 决定

Windows 上双击托盘打开的管理面窗口，创建时带 `skip_taskbar`，并且每次
`focus()` 重新显示后再补一次。窗口仍出现在 Alt+Tab，只是不占任务栏的一格。

同时给窗口配上品牌图标：`with_window_icon` 与 `with_taskbar_icon` 一起设。

macOS 分支不变，继续用 `ActivationPolicy::Accessory`。

## 为什么

macOS 的托盘是菜单栏小程序，窗口开出来不进 Dock。Windows 这边窗口由 tao
创建，`Parent::None` 那条路径会自动带上 `ON_TASKBAR`，于是每次双击托盘都会
在任务栏留下一格。两个平台上「一个后台程序、一个入口」的形态因此不一致：
同一个 Dec，mac 上安静待在菜单栏，Windows 上却像开了一个独立应用。

用户 2026-10-30 反馈「打开界面后能看到任务栏上有图标」，要求对齐。

图标一并处理是因为原先窗口没设图标，任务栏与 Alt+Tab 显示的是 exe 的通用
占位图——既然已经在这个位置动它，就顺手让它显示成自己。

## 被否方案

**手改 `WS_EX_TOOLWINDOW`。** 这是最直接的做法，但 tao 在窗口可见性变化时
用 `SetWindowLongW(GWL_EXSTYLE, ...)` 整段重写扩展样式，手加的位会被冲掉。
而 `focus()` 每次都调 `set_visible`，也就是说每拉一次窗口就会失效一次。
`skip_taskbar` 是 tao 自己的字段，创建时应用之后不再被动，路径稳定。

**用 `with_owner_window` 挂一个隐式 owner。** tao 在 `Parent::OwnedBy` 分支
不设 `ON_TASKBAR`，效果上也能去掉任务栏按钮。但仍然要自己拔 owner 窗口，
且 owner 销毁时子窗口会被系统一起带走，比多调一次 `set_skip_taskbar` 脆。

**干脆让窗口留在任务栏。** 否决理由：窗口本来就不该长期占位。它只在双击
托盘时存在，关掉就销毁，放进任务栏等于给一个「不留神的按钮」留了固定坑位。

**只在创建时调一次 `skip_taskbar`。** 不够。资源管理器在窗口重新显示、
最小化后还原时会重建任务栏条目，`DeleteTab` 的效果会被覆盖。所以 `focus()`
里每次重显后补一次。代价是一次 COM 调用，可以忽略。

## 已知边界

`DeleteTab` 是资源管理器的运行时状态，不写进窗口本身。Explorer 崩溃重启后
按钮有可能回来。考虑到窗口只在双击托盘时创建、关闭即销毁，实际碰上概率很低；
真碰上也可再双击一次托盘（走 `focus()` 补删）修掉。

Alt+Tab 里仍然有这一项。这是刻意保留的：窗口可能被别的应用盖住，留着
Alt+Tab 才能用键盘切回去，比彻底隐身更符合「它是个正常窗口」的预期。
