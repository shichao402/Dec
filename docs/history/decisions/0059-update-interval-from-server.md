# 自动更新的检查间隔由服务端 SSOT 决定，代理不落盘

## 背景

ADR 0058 把间隔写死在代理里：`Updater.Interval` 留零值，`Run` 兜底成 1 小时。
这在日常是对的——一小时轮询一次发布清单，代价可以忽略，发版后设备也能在一小时内对齐。

但它是常量，不是配置。发版当天想让设备早点对齐，或者一段时间内想少打点下载，
都只能改代码、发版、等设备更新到"能改间隔的那个版本"，绕一圈回到原点。
把这个值搬到服务端，改一次就作用于全部设备，不需要发版、不需要重启服务。

## 决策

1. 权威值存在服务端 SSOT：`config/settings.json`，字段 `update_check_interval_sec`。
   它与设备表、项目登记同一条提交路径，因此有 commit 可查、随冷备进 git 历史。
2. 代理本地不落盘。间隔通过 `hello` 响应下发（`update_check_interval_sec`），
   代理每次握手同步一次，重启后第一轮握手重新拿到。**没有**本地缓存文件，
   所以不存在"用了旧缓存"的窗口，也不需要额外的失效逻辑。
3. 取值区间 900 到 86400 秒（15 分钟到 24 小时），默认 3600 秒。
   写入路径越界直接拒绝；读取路径（含握手）越界则夹取到边界，不报错。
4. 下发 0 表示服务端没有给出有效值，代理继续用自己的默认 1 小时。
   读设置文件失败时下发 0，不让一个配置问题升级成"设备无法连接"。
5. 面板新增「设置」页。间隔的候选值按服务端返回的 min/max 渲染，
   不在前端硬编码边界；云端存了非预设值时单独插入一项显示当前值，
   避免页面默默跳到另一个数、用户一保存就把它改掉。
6. 写权限只给管理面与 CLI（`identity.CanManageDevices`）。读对所有来源开放。
7. 间隔变化是 `EventSettings`（TierFact），逐条记审计。

## 为什么不放进 config.json

`internal/agent/config.go` 的注释已经写明：代理只保存服务地址和设备身份，
"放进去的每一项都会变成换机器要重新配的负担"。间隔完全不符合这个标准——
它是云端统一下发的运行参数，本地存一份不但没用，还会引出一个无法回答的问题：
缓存和服务端不一致时听谁的。既然每次握手都能拿到，就不存。

## 为什么不加"关闭自动更新"的开关

ADR 0058 的整个出发点就是"发版即断供"：不自动更新时，每次客户端发版都会让
所有设备停在版本不对齐、停止下发的状态，直到有人逐台重装。给一个关闭开关，
等于把这个已经踩过的坑重新打开，而且它会藏在一个下拉框里，点下去没有任何提示
说明后果。真要临时关掉，`DEC_AUTO_UPDATE=0` 已经存在，那是排障手段，
不是配置项。

## 被否方案

- **存进 `config.json`**：见上。会破坏"配置只放身份与地址"的既有边界，
  并且每台机器多一份可能与云端不一致的状态。
- **新增独立的 `stateDir/settings.json` 只做本地缓存**：本来想这么做，
  但缓存的价值只在"断网时也能显示正确值"。而页面本来就有 `/api/status`
  显示最近一次握手拿到的值，那个值天然就是"最后一次成功同步的结果"，
  不需要另存一份文件来重复表达它。
- **给 `Updater.Interval` 加可写字段，由 `SetInterval` 直接改**：不够。
  循环在 `timer.Reset(interval)` 之后会睡满整个间隔，只改字段的话，
  把间隔从 24 小时调到 15 分钟要等到第二天才生效。必须有一个唤醒信号
  （`retuned` 通道）让循环立刻重排。
- **每次握手都无条件唤醒重排**：会把定时器变成"每轮握手重置一次"，
  实际检查节奏退化成握手间隔（30 秒），等于每 30 秒拉一次签名清单。
  只有值真的变化才唤醒（`SetInterval` 内部比较）。
- **让 MCP 也能改这个值**：AI 帮用户调配置是合理需求，但这个值影响全部设备的
  更新节奏，一次提示注入就能把间隔拉到 24 小时（让所有设备长期停在旧版）
  或压到下限（放大下载流量）。与吊销设备、改设备类型同属"不给 MCP"的一类。
- **在面板里硬编码 15 分钟到 24 小时的选项**：边界改了以后，页面会提交一个
  服务端拒绝的值，用户看到的是"保存失败"而不是"这项不支持"。
- **把间隔挂在 `sync` 而不是 `hello` 上**：`sync` 只在版本对齐后才会跑，
  而未对齐的代理恰恰最需要知道"多久查一次更新"。挂在 `hello` 上不存在这个分支。

## 后果

- 调间隔只需在面板改一次，全部设备在下一轮握手后按新节奏检查（最长延迟一小时内）。
- 正在等待的循环会被唤醒并按新值重新计时，已经睡下的时间不折算。
- 版本不对齐时仍由 `OnNotAligned` 立刻叫醒检查，所以间隔只决定"兜底探测"
  的频率，不影响发版后对齐的速度。
- 设置文件损坏不会阻断更新检查，只退化成默认 1 小时；坏值会被夹取而不是让读失败。
- 面板要能改这个值，前提是设备已经跑上带「设置」页的版本。旧版本代理不认识
  `hello` 里的新字段，按默认 1 小时走，不受影响。
