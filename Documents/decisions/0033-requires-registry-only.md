# 0033 — 订阅只从官方注册表安装

- **状态**：已接受
- **日期**：2026-09-24
- **关联**：[0029](0029-single-consumer-requires.md)、[0031](0031-control-plane-and-upstream-contribution.md)
- **影响范围**：`requires` pin、个人私仓解析、订阅面板、引导页

## 问题

0031 已经规定：个人私仓是控制面，提供方正文只在源仓和官方注册表。消费声明里每个提供方都 pin `latest` 或精确 `v*`。

代码只做了一半。已发布项目上的 `vault` pin 会收成 `latest`，但没进注册表的名字继续 pin `vault`，pull 仍从私仓取正文。私仓于是继续当第二套安装源。订阅面板也还把私仓项目列成可勾选项，保存时写回 `vault`。

## 决策

**`requires` 的 pin 只有 `latest` 和 `v*`。** 两者都从官方注册表安装。

`vault` 不再是 pin。旧文件里的这个字按下面的顺序处理：

1. 连上注册表时，已经发布的名字收成 `latest` 并写回。
2. 其余 `vault` pin 从消费声明里去掉并写回。
3. 连不上注册表时不改磁盘，避免把还能折叠的订阅抹掉。执行安装时这些名字也不从私仓取正文。

新的 `set_requires` 直接拒绝 `vault`。

用词：`project_name` 叫**本仓项目**，是这个目录正在写的项目。`requires` 的值叫**订阅版本**，只能是 `latest` 或某个 `v*`。

个人私仓继续做控制面：仓库地址、项目 stub（`name` / `title` / `tags` / `depends_on`）、密钥归属。本仓项目从工作树安装，不进 `requires`。私仓扫描只为本仓项目自己的资产服务，不沿 `depends_on` 把别的项目装进来。

订阅面板只列出注册表里已发布的项目，加上本工作区的本仓项目。本仓项目显示为必装，但不是订阅。

## 被否方案

- **留着 `vault` 给「还没发布的个人项目」**：这就是 0031 没收干净的那条安装通道。没进注册表的名字不该有订阅。
- **离线时也立刻删掉所有 `vault` pin**：已发布但这次没连上注册表的名字会被误删，下次只能重新订阅。
- **把用户机器上的 `agents-board` / `dec` 改写成 `latest`**：注册表里没有这两项，写成 `latest` 也装不上。清掉 pin，等它们被提供方发布后再订阅。
