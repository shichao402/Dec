# 实施计划：Pull 本地剪枝安全边界

顺序原则：先建立隔离区（所有后续改动都依赖它，且它单独就能消除数据丢失），再把"是否可删"的判定从执行逻辑里抽出来成为纯函数（预览与执行共用同一份判定，避免两套逻辑漂移），然后才对外暴露预览与恢复，最后处理中断并发与文档兼容。事件呈现放在中间，因为它改动最便宜且能立刻缓解"静默"感受。

- [ ] 1. 建立剪枝隔离区基础库
  - 新建独立包，实现"移入隔离区"的单条原子操作：同分区 `rename` 到隔离根下的时间戳子目录，保留原始相对路径与来源平面信息
  - 写入清单记录每条隔离项的原始路径、判定理由、时间、所属 bundle 与平面，供列表与恢复使用
  - 实现列表、按单条或整批恢复、到期清理、容量超限按最早优先清理四个操作
  - 保留期与容量阈值可通过配置读取，未配置时使用内置默认值
  - 隔离区不可写时返回错误，调用方据此中止剪枝，禁止退化为 `os.Remove`
  - 为上述行为编写单元测试，覆盖跨文件名冲突、目标已存在、清单损坏三种情况
  - _需求：3.1、3.2、3.4、3.5、3.6_

- [ ] 2. 抽取纯函数式剪枝决策器
  - 把 `pruneOrphanSecretsForTarget` 中的孤儿计算与落盘执行拆开：决策器只读扫描并返回待剪枝项列表，不产生任何文件副作用
  - 决策结果按"可重建 / 本地独有 / 来源不明"三类标注，每项附带判定依据与命中规则的说明
  - 保留类别与剪枝类别使用不同字段承载，避免下游只读一个列表而丢失保留原因
  - SSH Key 与 Secure Note 走同一份决策结构，`reconcileMissingVaultBundles` 的整目录场景也纳入
  - 决策器接收范围过滤参数（平面、bundle、路径前缀），为预览的局部计算复用
  - 编写表驱动测试，直接断言分类结果，不触碰真实写盘
  - _需求：1.4、2.1、2.2、2.3、2.5_

- [ ] 3. 落实"可重建才可删"的语义判定
  - 对本地条目判断其内容是否可由远端状态完整还原：远端存在同路径且内容一致、或属于程序派生的 bundle 目录，才归为可重建
  - 远端无对应项且本地内容无法溯源时，降级为本地独有并保留，同时在结果中给出保留理由
  - 把"远端不存在"与"本地可删"之间的等式在代码中用显式分支断开，禁止任何路径由前者直接推出后者
  - 补齐"本地含远端不存在内容时不被删除"的回归测试，作为该需求线的守护用例
  - _需求：2.1、2.2、2.3、2.4、9.3_

- [ ] 4. 执行路径改走隔离区
  - 将 `removeLocalSecureNoteFile` 的 `os.Remove` 与 `reconcileMissingVaultBundles` 的 `os.RemoveAll` 替换为隔离区移入，返回值区分"已隔离"与"已恢复"两类语义
  - 原 `RemovedSecretPaths` 等字段保留兼容，新增隔离路径与清单位置字段，避免既有消费方解析失败
  - 隔离动作失败时记录失败项与原因并继续后续条目，已完成的隔离记录不回滚
  - 空目录清理逻辑与隔离区解耦，避免把刚建立的非空隔离目录当空目录删掉
  - 补充集成测试，断言执行后原件不在原位、隔离区存在副本、清单可读出对应记录
  - _需求：3.1、3.6、5.4、8.1_

- [ ] 5. 新增 pull 预览能力
  - 实现预览入口，复用任务 2 的决策器，只计算不落盘，返回逐条待剪枝项、保留项及各自理由
  - 无待删条目时返回显式结论而非空集合；有待删条目时标注每项能否从远端重新拉回
  - 按既有构词规则命名为 `dec_preview_pull`，在工具目录、计划映射与服务分发表三处同步注册，描述中标注只读无副作用
  - 返回结构沿用预览类工具的分层形式（摘要、明细、事件），与上行预览保持字段命名一致
  - 执行阶段重新调用决策器校验，对已不满足条件的条目跳过并记录跳过原因
  - 测试覆盖预览不改动任何文件、预览与执行结论在状态未变时一致
  - _需求：1.1、1.2、1.3、1.5、7.1、7.3、7.4_

- [ ] 6. 补全事件的可追溯性
  - 服务端在操作结束时把本次事件流写入本地诊断记录，写入前过滤密钥值，仅保留路径等元信息
  - Console 的操作事件改为完整保留，去掉只留最近若干条的截断；成功提示仍按原时长自动消失，但结果区提供可展开的完整事件列表
  - 成功态展示从单一汇总改为汇总加逐条明细，确保每条剪枝的路径都可见
  - 查询接口暴露最近若干次操作的事件流，支持按操作标识回看
  - 测试覆盖"完成后仍能取到每个被剪枝路径"以及"诊断记录中不含密钥值"
  - _需求：4.1、4.2、4.3、4.4、4.5_

- [ ] 7. 新增隔离区恢复能力
  - 实现恢复操作，支持按单条或整批恢复到原始路径，目标已存在时报告冲突且不覆盖
  - 按既有动词体系命名为 `dec_restore_pruned`，同步注册到工具目录、计划映射与服务分发
  - 首次创建隔离区时在 pull 结果中给出隔离位置与保留期；状态查询中体现当前生效的保留期与剪枝默认行为
  - Console 提供对应的恢复入口与冲突提示
  - 测试覆盖单条恢复、整批恢复、冲突不覆盖、保留期届满后条目不可恢复
  - _需求：3.2、3.3、3.4、7.2、8.3、8.4、9.2_

- [ ] 8. 处理中断与并发安全
  - 将写操作与请求上下文解耦：剪枝阶段不再因调用方断开而中途放弃，已开始的单条动作必须走完
  - 对同一工作区的剪枝阶段加互斥，后到的 pull 请求串行等待或直接拒绝，不得并行进入
  - 中断后留下可识别标记，下次操作启动时检测并报告未完成的剪枝项
  - 补充测试：模拟请求上下文取消，断言无文件永久丢失、隔离区记录与文件系统状态一致；并发两次 pull 断言不产生交叉清理
  - _需求：5.1、5.2、5.3、5.4、9.4_

- [ ] 9. 兼容行为与文档同步
  - pull 默认行为改为不永久删除；提供显式参数恢复"严格对齐远端"的旧语义，并在结果与事件中留下审计记录
  - 为聚合式入口预留约束说明，明确其不得绕过决策器与隔离区，无人值守场景默认不剪枝
  - 更新工具说明、SKILL 文档与决策记录，说明隔离区位置、保留期、恢复方式与默认行为变化
  - 补充从旧版本升级后的首次 pull 说明，避免用户误以为删除消失了
  - _需求：6.1、6.2、6.3、6.4、8.1、8.2_

- [ ] 10. 端到端验收
  - 构造"本地含手工内容但远端无对应项"的仓库，跑完整 pull 后断言内容仍在且被标注为保留
  - 构造误删场景，使用恢复能力取回文件，断言路径与内容与隔离前一致
  - 断言预览、执行、事件、恢复四处的待剪枝清单在状态不变时彼此一致
  - 校验文档与实际行为一致，尤其是默认行为与保留期数值
  - _需求：9.1、9.2、9.3、9.4_
