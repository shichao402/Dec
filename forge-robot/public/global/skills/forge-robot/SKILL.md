# 设岗（forge-robot）

你是中枢。用户要设一个垂直岗时，按本清单交货。不要先讨论形态一/二/三。

## 先判断

- **只做一次** → 直接干完，不要设岗。
- **会重复出现** → 设岗。同类失败已被成功处理两次 → 必须补工具或规则，禁止继续商量。

## 向用户只要这 5 项

缺了再问，一次问完：

1. 岗位短名（小写+连字符，如 `svn-keeper`）
2. 日常动作（一句话）
3. 禁止事项（尤其是可能丢数据的）
4. 失败找谁：未知 → 中枢；可能丢数据 → 用户
5. 怎么跑：定时 / 中枢手动点一次

## 必须交出三样

不要只写理念。一次对话里交齐：

1. **手**：可运行的命令或 MCP（至少 `run` / `status`；需要时再加 `schedule`）
2. **错误码**：至少 `OK` / `NETWORK` / `LOCAL_CHANGES` / `AUTH` / `UNKNOWN`
3. **岗**：一份很短的岗位 Skill（见下方模板）

**禁止**：在工具进程里常驻会聊天的模型。Agent 只当学徒写手；上岗后中枢调接口。

## 验收

- [ ] 带着跑通一次
- [ ] 失败返回错误码，不是只有 `exit 1`
- [ ] 中枢下次只调接口，不聊天
- [ ] 岗位 Skill 写清：管什么、不管什么、何时升级给用户

## 岗位 Skill 模板

把 `<name>` 换成岗位短名，写入当前项目或用户约定的 skills 目录：

```markdown
---
name: <name>
description: 何时使用这个岗。日常应调它的工具/MCP，而不是重新发明步骤。
---

# <name>

- 管：<日常动作>
- 不管：<禁止事项>
- 调用：<命令或 MCP 名>
- 升级：LOCAL_CHANGES / AUTH / UNKNOWN → 带收据问用户；NETWORK → 重试后仍失败再问中枢
```

## 收据格式（失败时）

```text
岗: <name>
动作: <做了什么>
结果: <错误码>
现场: <路径/版本/是否有本地修改>
选项: <跳过 | 重试 | 请用户拍板>
```
