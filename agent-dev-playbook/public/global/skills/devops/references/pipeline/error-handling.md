# 错误处理指引

调用蓝盾 API 时若出现异常，按以下场景给出处理建议，不要盲目重试写操作（启动/取消/修改参数）。

## 入参校验（调用前）

在执行任何命令前，先校验用户提供的 ID 格式，格式不合法时应提示用户更正而非直接调用：

| 参数 | 合法格式 | 说明 |
|------|----------|------|
| projectId | 项目英文名 | 非空字符串，通常为小写字母/数字/短横线 |
| pipelineId | 以 `p-` 开头 | 如 `p-abc123`，不符合时提示可能为流水线名称，需先用 `pipelines` 命令查询 ID |
| buildId | 以 `b-` 开头 | 如 `b-xyz789`，不符合时提示需先用 `list` 命令查询构建 ID |

## 常见错误场景

| 现象 | 可能原因 | 处理建议 |
|------|----------|----------|
| `URL Error` / 超时（30s） | 网络不通、API 网关不可达 | 提示用户检查网络/VPN，稍后重试；读操作可重试，写操作需用户重新确认后再试 |
| `HTTP Error 401` | 访问令牌缺失或失效 | 提示用户检查并更新[统一鉴权配置](../auth-setup.md) |
| `HTTP Error 403` | 无该项目/流水线操作权限 | 提示用户确认账号是否有对应流水线权限，不要重试 |
| `HTTP Error 404` | projectId/pipelineId/buildId 不存在 | 提示用户核对 ID；可建议先用 `pipelines` 或 `list` 命令查询正确 ID |
| `HTTP Error 400` | 参数错误（如 buildNo 冲突、JSON 格式错误） | 检查 `--params` JSON 是否合法、参数名是否存在；修改参数失败时按脚本提示的可用参数列表更正 |
| `HTTP Error 5xx` | 服务端异常 | 非用户问题，提示稍后重试，不要反复重试写操作 |
| `JSON Decode Error` | 响应非 JSON / `--params` 解析失败 | 检查 `--params` 是否为合法 JSON 字符串 |
| `参数 'X' 在流水线中不存在` | 修改参数时参数名拼写错误 | 参照脚本输出的可用参数列表，更正参数名后重新经用户确认再执行 |

## 通用原则

- **读操作**（pipelines/list/startup-info/status）失败可在排查后自动重试。
- **写操作**（start/stop/update-params）失败后**禁止自动重试**，必须向用户说明失败原因并重新获得确认。
- 出现权限类错误（401/403）时，优先引导用户处理令牌或权限，不重复调用。
