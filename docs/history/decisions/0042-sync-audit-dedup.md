# 0042 sync 审计按内容指纹降噪，密钥下发不降噪

> **已被 [0043](0043-audit-tiers.md) 取代。**
>
> 方向（给 sync 降噪）是对的，但方案不够彻底：故障后期内容每轮都在变
> （说明行被反复叠加），内容指纹全不同，降噪完全失效；而且"忽略哪些字段"
> 的规则散落在调用点，容易再次漂移。0043 改为在日志层按事件级别分级，
> 用 (事件, 设备, 来源, 对象) 按小时聚合，并加了单键、全局、桶数三重上限。
> 本文保留作为当时的推理记录。

## 背景

修完说明行（见 [0041](0041-notice-rendered-by-server.md)）之后，回头看清那 8.4 万条记录
是怎么把一个有用的信号埋掉的。

审计里 `sync` 事件的语义是"服务端给某台设备下发了内容"。正常使用下它的频率很低：
改一次资产、装一台新设备、换一份订阅，各留一条。但在重写循环期间，同一台设备
每完成一轮对账就留下一条，内容完全一样，只有 `Subject`（revision）可能不同。

于是真正需要被看见的那条信息——"每小时多出几千条 sync"——反而看不见了。
`git log` 全是 `审计 N 条`，`events/*.hour.jsonl` 每行一模一样。
事后判断故障时，是磁盘和内存先报警才找到原因，审计本身没起到任何提示作用。

审计的价值不在于记得多，而在于记得准。一条内容重复十万次的日志，
信息量等于零。

## 决策

1. **按"内容指纹"降噪，不按事件类型整体关掉。** `syncSignature(deviceID, batch)`
   用 sha256 拼设备 ID + 每个文件的 `ID`/内容哈希/`Key` + 每个删除的 `ID`。
   同一签名在 `syncQuiet`（30 分钟）内只记第一条。
2. **指纹刻意不含 revision。** 幂等重发时 revision 可能因为别的设备写入而变，
   但推出去的内容完全相同，在审计里属于同一条事实。带上 revision 就等于没降噪——
   故障场景下每轮 revision 都可能不同。
3. **指纹含设备 ID。** 同一份内容推给两台设备是两条独立事实，
   审计要能回答"这份内容送到过哪些机器"，跨设备合并会毁掉这个能力。
4. **密钥下发不参与降噪。** `recordSecretDelivery` 独立记录，
   注释写明理由：吊销设备后要能回答"哪些内容曾经送出服务端"，
   少记一条就可能漏掉一次密钥外流。安全追溯优先于日志整洁。
5. **只降噪重复，不降噪首次。** 静默期过去后同一签名会重新记录，
   否则审计里会看不出这台设备还活着——一台每天正常对账的设备
   也应该每天留下一条痕迹。
6. **表本身要能收敛。** 超过 512 条时清理四倍静默期之前的条目，
   避免"内容不断变化"时这张内存表无限增长——那也是这次故障的一种形状。

## 为什么 30 分钟

- 正常使用不会在半小时内重复下发同一批内容，所以不会掩盖真实操作；
- 故障级重写（每秒一轮）会留下每小时两条的痕迹：量级差异一眼可见，
  又不至于把日志刷爆；
- 一天最多 48 条同内容记录，即使长期存在也不构成体积问题。

## 被否方案

- **A. 直接不再记录 sync。** 需求 15.3 明确要求审计覆盖下发。
  真出问题时"推了什么给哪台机器"是第一个要回答的问题。
- **B. 按设备每小时最多记一条。** 会丢掉"同一小时内推了两批不同内容"这个事实，
  而那可能正是需要追溯的操作。指纹方案只在内容相同时合并。
- **C. 在 `audit.Log` 层做通用去重。** 审计层不知道事件语义，
  只能按键值完全相等判断；而这里两条记录恰恰 `Subject` 不同，
  通用去重抓不到。
- **D. 在写入磁盘前聚合、按小时汇总条数。** 引入"汇总记录"这种第二形态，
  读审计的人要同时理解明细和汇总两套语义。降噪之后量级已经足够小，
  不值得再加一层。

## 运维影响

- 故障排查时看到的是"每条内容一行"，重复次数不再体现在行数上。
  需要精确次数时应看代理侧日志或服务端请求计数，审计不承担计数职责。
- 重启服务后降噪表清空，第一轮会补记一遍当前内容。这是可接受的，
  也恰好让"服务重启过"在审计里可见。
- 存量 8.4 万条历史记录不迁移、不删除：审计是只追加档案，改历史比留着噪声更糟。
  它们的价值在于证明那次故障的规模。

## 验证

- `TestSyncSignatureIgnoresRevision`：只差 revision 的两批内容视为同一指纹。
- `TestSyncSignatureDistinguishes`：内容、文件、设备、删除任一变化都会改变指纹。
- `TestSuppressSyncDedupes`：窗口内重复下发只放行第一次。
- `TestSuppressSyncReopensAfterQuiet`：静默期后重新记录。
- `TestSuppressSyncDifferentDevices`：降噪按设备隔离。
- `TestSuppressSyncPrunesStale`：过期条目被清理。
