# Issue Handler 执行手册

## 来源

- 提炼自内部项目 issue 自动处理 agent 的生产实践
- `scripts/lock.py` 为本 skill 独有可执行件，随 skill 分发

## 五步流程 SOP

每轮 tick 按顺序过五步；前两步是门槛判定，过不了就停在对应等待态。

### 1. 重复判定

- 检索：用标题关键词与正文特征搜索项目历史 issue（open 与近期
  closed），对比四维：目标现象、复现条件、根因假设、影响范围。
- 判定：四维中前三维高度一致视为疑似重复；拿不准不强行判重，
  按第 2 步信息判定处理。
- 动作：回复指出疑似重复对象（附链接），请求提交人确认，
  置状态 `waiting-dup-confirm`。
- 超时：默认 7 天无确认，自动关闭并注明可补充证据重开。

### 2. 信息充分性判定

必要字段清单，缺任一即请求补充：

- 目标/期望行为
- 实际现象
- 复现步骤或触发条件
- 版本/环境信息

- 动作：回复逐项列出缺失字段，置状态 `waiting-info`。
- 超时：默认 7 天无响应，自动关闭。

### 3. 处理

- 先过 rule 三条红线（ADR/架构/roadmap），任一不满足转人工。
- 为该 issue 单独开 MR/PR 修复；分支命名建议
  `issuefix/<issue编号>-<slug>`。
- 串行推进：同一时间只做一个任务，完成前不接新任务。

### 4. 验证

- 修复合入预发布环境，自测通过。
- 回复提交人：修复内容 + 预发布环境地址，请求确认，
  置状态 `waiting-verify`。

### 5. 收尾

- 提交人确认后发正式版；发版前核对本次只含已确认修复集
  （发版隔离红线）。
- 关闭 issue。

## 回复模板库

### 疑似重复

> 疑似与 #<编号> 重复（目标现象与复现条件高度一致）。
> 请确认是否为同一问题；确认重复将关闭本 issue，
> 如有差异请补充说明。

### 请求补充信息

> 还缺以下信息，补充后继续处理：
> 1. <缺失字段>
>
> 7 天无响应将自动关闭。

### 修复完成请确认

> 已修复并合入预发布环境：<地址>
> 修复内容：<摘要>
> 请在该环境确认问题是否解决；确认后发正式版并关闭本 issue。

### 超时关闭

> 等待 <确认/补充> 超过 7 天未响应，先关闭本 issue。
> 如仍需处理，补充信息后重开即可。

## 状态机

| 状态 | 等待信号 | 动作 | 去向 |
|---|---|---|---|
| `waiting-dup-confirm` | 提交人确认 | 确认重复则关单；否认则过信息判定 | waiting-info / closed |
| `waiting-info` | 提交人补充 | 充分则红线检查后进入处理 | processing / 转人工 |
| `processing` | MR 合入预发布且自测通过 | 回复请确认 | waiting-verify |
| `waiting-verify` | 提交人确认 | 发正式版（核对修复集）后关单 | closed |
| `stale`（异常） | tick 发现状态陈旧 | 重查 issue 最新状态后续跑 | 对应状态 |

状态记录落在 issue 评论或项目约定的本地状态文件；
跨 tick 恢复以远端 issue 状态为准。

## 工作空间防重锁

粒度为工作空间级（串行语义 + 共享 MR/构建/发布资源）。

```bash
# 获取（被占退出码 1；陈旧锁自动抢占）
python3 scripts/lock.py acquire --owner <执行流名>

# 心跳（长任务期间定期续期）
python3 scripts/lock.py heartbeat

# 释放
python3 scripts/lock.py release

# 查看状态
python3 scripts/lock.py status
```

- 锁目录 `<root>/.locks/issue-handler/`（`--root` 默认当前目录，
  环境变量 `ISSUE_HANDLER_LOCK_DIR` 可覆盖）。
- 锁是运行时产物，锁目录应进项目 `.gitignore`。
- 抢占只认心跳：持有者崩掉后心跳停止，超阈值（默认 300s）
  下一执行流可安全接管。

- 预发布/正式环境地址与发版方式
